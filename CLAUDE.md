# Инструкции для агента, работающего в этом репозитории

## Что это за проект

Nagi — self-hosted система исследования и управления портфелем для одного
частного инвестора без статуса квалифицированного, российский рынок,
горизонт годы. Не HFT, не внутридневная торговля, не передача счёта под
управление ИИ.

Текущая стадия: **исследование и архитектура**. Продакшн-кода нет.

## Текущее состояние и следующий шаг

> Этот раздел обновляется при завершении каждой фазы. Если он расходится с
> фактическим содержимым репозитория — верь репозиторию и поправь раздел.

**Завершено:** исследование рынка, протокол экспериментов, архитектура,
конструкция портфеля, план по уровням. Все решения зафиксированы в `docs/`.

**Следующая фаза: уровень L0** — продуктовая и информационная выполнимость
(см. `docs/ROADMAP.md`). Первые три задачи по приоритету:

1. Выяснить, есть ли у T-Invest **минимальная комиссия за сделку** и какая. При
   портфеле 500 000 ₽ это определяет минимальный размер позиции и число бумаг —
   от этого зависит вся конструкция портфеля.
2. Найти работы по **факторным премиям на MOEX после 2022 года**. Если премии не
   воспроизводятся, слой отбора отдельных бумаг не нужен, и система сводится к
   распределению между классами активов. Это самый крупный открытый вопрос.
3. Уточнить **условия ИИС-3** для счетов, открытых в 2026 году, и порядок
   сальдирования убытков.

L0 не завершён. Переходить к L1 (каркас проекта и данные) до закрытия этих
пунктов не следует — они меняют требования.

## Зафиксированные параметры (менять только по решению владельца)

| Параметр | Значение |
|---|---|
| Вселенная | мультиактив: акции, ОФЗ, БПИФ, металлы |
| Расчётный размер портфеля | до 500 000 ₽ |
| Исполнение | только рекомендации; автоисполнение — решение после L4 |
| Язык документации и комментариев | русский |
| Бюджет оборота | около 100% в год, примерно 2 сделки в месяц |

## Принципы, которые нельзя нарушать

1. Намерение совершить сделку формирует детерминированный версионированный
   алгоритм, **никогда не языковая модель**. LLM допустима только как офлайн-
   разметчик новостей с версионированным промптом и бюджетом.
2. Скор **не является изменяемой колонкой** таблицы инструментов. Только
   неизменяемый `strategy_version` плюс append-only `signal_observation`.
   Изменение одного веса создаёт новую версию, а не правит старую.
3. Никаких решений на основе данных, недоступных на момент решения. Каждая
   строка несёт `available_at`; нарушение point-in-time — это баг, а не мелочь.
4. Продажа обосновывается переходом портфеля в целом, а не низким скором
   позиции. Не сортировать скор и не продавать худшее.
5. Ожидаемая доходность не оценивается в абсолютных величинах нигде. Скор
   задаёт состав портфеля, веса внутри класса активов — равные.
6. Результат измеряется только после комиссий, спреда, проскальзывания и
   налогов, против инвестируемого бенчмарка. При высокой ключевой ставке
   честный конкурент — фонд денежного рынка, а не индекс акций.
7. Песочница и теневые портфели не дают права торговать реальными деньгами.

## Учётные данные

Регламент: `docs/operations/credentials.md`. Кратко и обязательно к соблюдению:

- **Никогда не просить владельца прислать токен в переписку.** Он попадёт в
  транскрипт сессии. Владелец кладёт секрет в файл сам и сообщает только путь.
- Секреты живут в `~/.config/nagi/secrets.env` с правами 600, **вне
  репозитория**. Не создавать `.env` внутри рабочей копии.
- Значение токена **не печатать никогда** — ни в вывод команды, ни в лог, ни в
  сообщение об ошибке, ни в сообщение владельцу.
- До уровня L7 нужен **только токен на чтение**. Если работа требует прав на
  торговлю раньше — это ошибка проектирования, остановиться и сообщить.
- Выходя на уровень, которому нужен токен: объяснить владельцу какой тип и
  зачем, дать команды для создания файла, дождаться подтверждения. Не начинать
  работу с API до этого.
- Первым обращением к API убедиться, что токен действительно только на чтение.
  Если торговая операция не отклоняется — остановиться и предупредить владельца.

**Ближайшая потребность:** уровень L0 требует токена только на чтение для зонда
возможностей API.

## Особенности окружения

- **`WebSearch` и `WebFetch` в этой среде ограничены** — домены не проходят
  проверку, а бюджет поиска быстро исчерпывается субагентами.
- **`curl` из Bash работает без ограничений.** Через него получены тексты НК РФ
  с consultant.ru, директива UCITS, данные MOEX ISS, научные статьи в PDF.
  Для поиска годится `https://lite.duckduckgo.com/lite/?q=...` с обычным
  User-Agent. Используй это вместо вывода «источник недоступен».
- Фильтр вывода вырезает денежные суммы. Если нужно прочитать число из
  документа, разведи цифры разделителями перед печатью.

## Конвенции

- Документация и комментарии в коде — по-русски. Идентификаторы в коде —
  по-английски.
- Числа в документах должны быть воспроизводимы. Расчёты живут в
  `docs/decisions/cost_and_power.py`; при изменении допущений об издержках
  правится скрипт, затем документ, а не наоборот.
- Каждое утверждение о внешнем мире — со ссылкой на источник в реестре
  свидетельств `docs/research/market-research.md`. Разделять подтверждённые
  факты и наши выводы.
- Неподтверждённое помечать явно. Формулировка «требует проверки» лучше
  уверенного вымысла.
- Старые артефакты (`main.ipynb`, `req.txt`, `shares_dataset.csv`) переносить в
  `legacy/` только после появления нового каркаса. Скор и «knapsack» из
  ноутбука не переносить — они ошибочны, разбор в `market-research.md`.

## Чего не делать

- Не начинать писать код до закрытия L0: неизвестные параметры изменят
  требования.
- Не добавлять микросервисы, Kafka, Kubernetes, векторную БД, feature store.
  Нагрузка их не оправдывает, обоснование в архитектуре.
- Не подключать Airflow. Планировщик — таблица заданий в PostgreSQL с
  advisory lock.
- Не вводить второй рантайм. Всё на Python.
- Не переиспользовать код парсера из `News-Aggregator-HSE-v1` — только паттерны.
- Не добавлять новостной слой раньше уровня L6 и раньше, чем факторное ядро
  докажет работоспособность.
- Не трогать боевой счёт. Токен только на чтение до отдельного решения владельца.
