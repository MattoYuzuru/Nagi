# Учётные данные: когда, какие и куда

Статус: операционный регламент
Дата: 2026-08-01

Документ отвечает на вопрос «когда владельцу нужно выпустить токен T-Invest и
куда его положить». Агент, работающий в репозитории, обязан запрашивать
учётные данные по этому регламенту и не имеет права от него отклоняться.

---

## Главное правило: не присылать токен в чат

**Никогда не вставляй токен в переписку с агентом.** Всё, что попало в диалог,
остаётся в транскрипте сессии, в файлах задач и потенциально в логах. Токен,
однажды показанный в чате, следует считать скомпрометированным и отозвать.

Правильный порядок:

1. владелец сам создаёт файл с секретом вне репозитория;
2. владелец сообщает агенту **только путь** к файлу;
3. агент читает переменную окружения из этого файла, но **никогда не печатает
   её значение** — ни в вывод команды, ни в лог, ни в сообщение.

То же относится к номерам счетов и содержимому брокерских отчётов.

---

## Куда складывать

Вне репозитория, с правами только для владельца:

```
mkdir -p ~/.config/nagi
touch ~/.config/nagi/secrets.env
chmod 600 ~/.config/nagi/secrets.env
```

Содержимое (пример, значения подставить свои):

```
NAGI_TINVEST_TOKEN_READONLY=<токен только на чтение>
NAGI_TINVEST_TOKEN_SANDBOX=<токен песочницы, появится на L5>
NAGI_TINVEST_ACCOUNT_ID=<идентификатор счёта>
```

Почему вне репозитория, а не в `.env` внутри с записью в `.gitignore`: файл
внутри рабочей копии рано или поздно попадёт в архив, в дамп, в скриншот или в
случайный `git add -A` при изменившемся `.gitignore`. Вне репозитория этот класс
ошибок отсутствует. Для продакшена на VPS — файл, читаемый только root, либо
менеджер секретов провайдера.

Запрещено: хранить токен в коде, в ноутбуке, в конфиге, попадающем в Git, в
переменных окружения CI, в браузерном хранилище, в базе данных проекта.

## Когда какой токен нужен

| Уровень | Токен | Область доступа | Зачем |
|---|---|---|---|
| **L0** | только чтение | все счёта, read-only | зонд возможностей API: покрытие фундаментала, лимиты, наличие минимальной комиссии, полнота корпоративных действий |
| **L1–L3** | тот же, только чтение | read-only | загрузка справочников, истории котировок, дивидендов, событий |
| **L4** | тот же, только чтение | read-only | чтение реального портфеля для сверки рекомендации с фактом |
| **L5** (условный) | отдельный, песочница | sandbox | проверка контракта адаптера, без денег |
| **L7** (условный, отдельная авторизация) | полный доступ | **строго один счёт** | выставление реальных заявок |

До L7 **полный доступ не нужен вообще**. Если агент просит токен с правом
торговли раньше — это ошибка, отказывай.

Разные токены для разных задач обязательны: сборщик данных не должен физически
иметь возможность выставить заявку. Это не формальность, а единственная защита
от бага в исследовательском коде.

---

## Как выпустить

В приложении или личном кабинете T-Инвестиций: раздел с настройками API,
кнопка выпуска токена, выбрать **«только чтение»** для всех уровней до L7.

Что важно знать заранее (подтверждено официальной документацией, см. S8 в
`docs/research/market-research.md`):

- **токен показывается один раз** при создании — потерял, выпускай новый;
- **токен истекает через три месяца после последнего использования**, поэтому
  нужен либо регулярный прогон, либо процесс перевыпуска;
- существуют токены только на чтение, полного доступа, на конкретный счёт и
  для песочницы;
- для работы автоматической торговли требуется отключить подтверждение сделок
  кодом — **делать это только на L7 и только после отдельного решения**, не
  раньше.

---

## Ротация и отзыв

Отзывать немедленно, если: токен попал в чат, в коммит, в лог, в скриншот; в
репозитории появился незнакомый код, имеющий доступ к секретам; истёк срок и
выпущен новый; завершилась фаза, для которой токен создавался.

Плановая ротация — раз в три месяца, что естественно совпадает со сроком
истечения.

---

## Что должен сделать агент при выходе на уровень, требующий токена

1. Сообщить владельцу: какой уровень, какой тип токена, зачем именно он нужен.
2. Дать команды для создания файла секретов, если файла ещё нет.
3. Дождаться, пока владелец подтвердит, что файл заполнен, — **не предлагать
   прислать токен в переписке**.
4. Читать значение через переменную окружения, не печатать его, не сохранять в
   файлы репозитория, не включать в сообщения об ошибках.
5. При первом обращении к API проверить, что токен именно на чтение: попытка
   торговой операции должна отклоняться. Если не отклоняется — остановиться и
   сообщить владельцу, что выпущен токен с лишними правами.
